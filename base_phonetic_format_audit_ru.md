# Phonetic-format audit Базы B0–B7

## Критический вывод

Обнаружено нарушение обязательного формата Taika: **каждый слог в `phonetic` должен завершаться тоновой стрелкой**. Эталонный формат использует `→` для ровного/среднего движения, `↗` для подъёма и `↘` для падения.

В текущей Базе проверено **394 phonetic records и 987 слоговых tokens**. Из них:

| Показатель | Результат |
|---|---:|
| Tokens со стрелкой | 925 из 987 |
| Tokens без стрелки | 62 из 987 |
| Records с нарушением | 36 |
| Курсы с нарушением | B1, B3, B4, B5, B6, B7 |
| B0 нарушений | 0 |
| B2 нарушений | 0 |

Это не косметическая проблема. Стрелка — часть методики: она показывает пользователю, как вести голос и где находится ударное тоновое движение. Запись без стрелки делает карточку неполной и может закрепить неправильное произношение.

## Главная причина

Из 36 нарушенных records **32 появились в последней content migration B3–B7**, а 4 были внесены в более раннюю migration B1 с repair-фразами. То есть это не старый случайный долг каталога, а конкретная ошибка в наших последних изменениях.

Особенно критичен B4: все 24 новых records в уроках числительных были записаны без стрелок. Формулы чисел образовательной ценности не теряют, но phonetic-поле сейчас не соответствует системе Taika.

## Примеры нарушения

| Карточка | Сейчас | Должно быть по формату |
|---|---|---|
| Один | `нынг` | `нынг→` или другой проверенный тоновой вариант |
| Одиннадцать | `сип эт` | `сип→ эт↘` или проверенная canonical-разметка |
| Двадцать один | `йи сип эт` | `йи→ сип→ эт↘` или проверенная canonical-разметка |
| Не понимаю | `май кау-джай` | `май↘ кау→ джай→` или canonical-разметка |
| Да, беру/давай | `ау лёй` | Каждая syllable с соответствующей стрелкой |
| Ничего страшного | `май пен рай` | `май→ пен→ рай→` только после проверки реальных тонов |

В таблице выше направление приведено как пример формата, а не как разрешение автоматически проставить стрелки. Для каждого нового слова и casual-единицы тон нужно проверить по Thai source/canonical bank и прослушиванию носителя.

## Что нужно исправить

### P0 — немедленно

Исправить все 36 records и прогнать validator, который проверяет, что каждый token в `phonetic` заканчивается на `→`, `↗` или `↘`. Нельзя просто добавить одинаковую стрелку в конец всей строки: стрелка нужна каждому слогу.

Для B4 необходимо отдельно проверить все числительные: `сип эт`, `йи сип`, `йи сип эт`, `рой`, `пхан`, `мыэн`, `сэн`, `лан`. Числовая логика верная как educational content, но tone markup должен быть подтверждён для каждого компонента.

### P0 — canonical consistency

Одинаковые Thai phrases должны иметь одинаковую phonetic-разметку во всех курсах, если контекст не меняет произношение. Нужно сравнить B1–B7 с `curriculum_lemma_canon.json`, а дубли вроде «спасибо», «вода», «счёт», «до встречи» не редактировать вручную в каждом месте.

### P1 — новые casual/slang records

Casual и slang нельзя добавлять без phonetic arrows. Для каждой современной формы нужно хранить проверенный phonetic variant и пометку регистра. Если точная форма не подтверждена, карточку лучше временно оставить нейтральной, чем выпускать сомнительную транслитерацию.

## Безопасный порядок remediation

1. Сначала сделать canonical map для всех 36 проблемных records.
2. Затем применить точечную замену только в `steps.json`.
3. Проверить, что B0 и B2 не изменились, а B1/B3–B7 получили только phonetic corrections.
4. Запустить machine validator по всем 394 records.
5. Отдельно проверить duplicate phrases на одинаковую стрелочную разметку.
6. Только после этого создавать commit и push.
