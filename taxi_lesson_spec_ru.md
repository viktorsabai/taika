# Эталонный урок Taika: «Такси — от посадки до оплаты»

**Статус:** методический эталон для переработки текущего `course_l_2`  
**Целевая аудитория:** русскоязычный пользователь, живущий или часто передвигающийся по Таиланду  
**Рекомендуемое место в программе:** после `course_b_1` и базового блока `course_b_4`; желательно после первого знакомства с tone feedback в `course_b_2`  
**Формат:** один законченный бытовой сценарий, а не список слов  
**Продолжительность:** 8–12 минут первого прохождения; 3–5 минут повторного retrieval

> **Итоговый Can-Do outcome:** «Я могу посадить такси, назвать пункт назначения, дать простое направление, уточнить цену или счётчик, попросить остановиться и завершить поездку без перехода на английский».

## 1. Что пользователь должен уметь после урока

Урок не обязан научить пользователя всему, что может произойти в такси. Его задача — дать надёжный минимальный маршрут, который реально можно завершить: **вызвать/остановить → назвать destination → уточнить оплату → дать одно направление → попросить остановиться → оплатить → попрощаться**.

| Навык | Минимальный observable outcome |
|---|---|
| Начало поездки | Пользователь может сказать, куда едет, с вежливым окончанием |
| Цена и способ расчёта | Пользователь может спросить цену и попросить ехать по счётчику |
| Навигация | Пользователь может сказать «прямо», «налево/направо» и назвать простую точку |
| Остановка | Пользователь может попросить остановиться здесь или у входа |
| Завершение | Пользователь может сообщить об оплате, попросить не давать сдачу и попрощаться |
| Repair strategy | Пользователь может попросить подождать или повторить медленнее, если не понял |

**Не является целью урока:** грамматически разобрать все конструкции, выучить полный транспортный словарь или проверить восемь фраз на идеальное произношение за один проход.

## 2. Prerequisites и вход

Перед уроком пользователь должен уже понимать базовый формат карточки: русский смысл, Thai original, русская транслитерация и voice attempt. Желательно, чтобы он уже встречал `кхрап`, числа 1–100 и базовые направления. Если prerequisite не выполнен, приложение не должно блокировать урок; оно показывает короткий inline reminder, а не отправляет пользователя в другой курс.

| Prerequisite | Откуда | Как использовать |
|---|---|---|
| Вежливое окончание `кхрап` | `course_b_1` | Не объяснять заново длинно; подсветить в карточке |
| Числа и цена | `course_b_4` | Нужны для `рой бат`, `сон рой бат` и price question |
| Направления | `course_b_4` | Повторить в taxi context, не создавать отдельный vocabulary drill |
| Базовый tone feedback | `course_b_2` | Использовать только один pronunciation focus за попытку |

## 3. Сценарная рамка

В начале пользователь видит не «Урок 3 из 7», а ситуацию:

> **Ты садишься в такси после аэропорта. Нужно доехать до кондо, понять цену, дать водителю направление и выйти у входа.**

На экране можно показать компактную route line: **садимся → едем → уточняем → останавливаемся → оплачиваем**. Это не декоративный progress bar: каждый этап должен открываться после действия пользователя.

В уроке используется один основной персонаж — пользователь — и один собеседник — водитель. Не нужно вводить несколько голосов и веток до первой успешной поездки.

## 4. Lesson loop

| Этап | Действие | Результат |
|---|---|---|
| Hook | Пользователь выбирает, что нужно сделать в такси | Формируется цель: «доехать и не растеряться» |
| Notice | Одна phrase card с контекстом и функцией | Пользователь понимает, зачем фраза нужна |
| Listen | Slow version → natural version | Слышит ритм и финальный tone |
| Speak | Повторяет фразу в микрофон | Делает собственную попытку |
| Feedback | Получает максимум два actionable cues | Понимает следующий шаг, а не только score |
| Retrieve | Через 1–2 карточки вспоминает фразу | Проверяется recall без полного prompt |
| Transfer | Использует конструкцию с новым destination/суммой | Проверяется перенос навыка |
| Exit | Проходит короткий taxi dialogue | Видит, готов ли к следующему маршруту |

Каждое состояние должно быть пользовательским. Нельзя автоматически перескакивать от listen к speak или от score к следующей карточке.

## 5. Карточка нового формата

На первой встрече карточка не должна перегружать экран крупным тайским текстом. Иерархия должна быть такой: **русский смысл → русская транслитерация → Thai original по запросу/вторым слоем → pronunciation cue → действие**.

### Обязательные поля карточки

| Поле | Пример |
|---|---|
| `canonical_content_id` | `taxi.destination.airport_polite` |
| `ru` | «В аэропорт, пожалуйста» |
| `thai` | `ไปสนามบินครับ` |
| `phonetic` | `пай са нам бин кхрап` |
| `context` | taxi / destination / polite request |
| `function` | назвать пункт назначения |
| `pronunciation_focus` | ровный ритм; мягкое финальное `кхрап` |
| `listen_variants` | slow, natural |
| `tip` | «Не дроби фразу на отдельные слова; скажи её одним направлением» |
| `retrieval_type` | guided recall / scenario transfer |
| `next_action` | сказать без русского prompt |

## 6. Core phrase set

В качестве основы используются уже существующие records из `course_l_2`. Их не нужно копировать в новый lesson; нужно назначить canonical IDs и lesson-specific exposure types.

| Порядок | Фраза | Функция в сценарии | Pronunciation focus | Exposure |
|---:|---|---|---|---|
| 1 | **В аэропорт, пожалуйста** — `ไปสนามบินครับ` — *пай са нам бин кхрап* | Назвать destination | Не терять финальное `кхрап`; держать фразу как единый ритмический блок | introduce |
| 2 | **Сколько стоит?** — `เท่าไหร่ครับ` — *тао рай кхрап* | Уточнить цену | Вопросительная интонация в конце, но без крика; `кхрап` остаётся коротким | introduce |
| 3 | **По счётчику** — `ตามมิเตอร์` — *там ми то* | Обсудить способ расчёта | Не ускорять середину; три коротких ритмических блока | guided retrieval |
| 4 | **Прямо, потом налево** — `ตรงไปแล้วเลี้ยวซ้าย` — *тронг пай леу лиао сай* | Дать маршрут | Связать фразу в направление, не произносить как восемь отдельных карточек | scenario transfer |
| 5 | **Остановите здесь, пожалуйста** — `จอดตรงนี้ครับ` — *чот тронг ни кхрап* | Завершить поездку | Финальное снижение; не проглатывать `ни` перед `кхрап` | introduce |
| 6 | **Вот оплата, спасибо** — `นี่ครับขอบคุณ` — *ни кхрап кхоп кхун* | Передать оплату и завершить | Пауза после `кхрап`; благодарность — отдельный мягкий блок | guided retrieval |
| 7 | **Сдачи не надо** — `ไม่ต้องทอน` — *май тон тхон* | Завершить оплату | Не добавлять эту фразу в первую попытку, если пользователь ещё не освоил базовый close | optional extension |
| 8 | **Подождите немного** — `รอหน่อยนะ` — *ро ной на* | Repair/задержка | Мягкое окончание `на`, без жёсткой команды | repair strategy |

В первом прохождении достаточно 6 core phrases. Фразы «сдачи не надо» и «подождите немного» открываются как optional extension или появляются в transfer-сценарии. Так урок сохраняет лёгкость и не превращается в словарь поездки.

## 7. Как выглядит одна карточка на экране

**Ситуационный заголовок:** «Водитель спрашивает, куда ехать»  
**Главный смысл:** «В аэропорт, пожалуйста»  
**Транслитерация:** *пай са нам бин кхрап*  
**Thai original:** раскрывается вторым визуальным слоем после tap или listen  
**Микро-tip:** «Скажи destination одним ритмом. Финальное `кхрап` — короткое и спокойное»  
**Primary CTA:** «Послушать» → «Сказать самому» → «Повторить ещё раз»

После voice attempt feedback должен иметь максимум два слоя:

| Feedback | Пример |
|---|---|
| Что уже получилось | «Фраза собрана целиком; destination звучит понятно» |
| Один следующий фокус | «Попробуй ещё раз чуть короче закончить `кхрап`» |

Score может присутствовать вторично, но не должен заменять объяснение. Фраза «91/100» без cues не является полноценным обучающим feedback.

## 8. Основной диалог внутри урока

После отдельных карточек пользователь проходит guided dialogue:

| Шаг | Водитель | Пользователь |
|---:|---|---|
| 1 | «Куда едем?» | `ไปสนามบินครับ` — «В аэропорт, пожалуйста» |
| 2 | «По счётчику?» / price prompt | `เท่าไหร่ครับ` или `ตามมิเตอร์` |
| 3 | «Куда дальше?» | `ตรงไปแล้วเลี้ยวซ้าย` — «Прямо, потом налево» |
| 4 | Подъезжаем | `จอดตรงนี้ครับ` — «Остановите здесь» |
| 5 | Оплата | `นี่ครับขอบคุณ` — «Вот оплата, спасибо» |

На первом проходе пользователь может нажимать подсказку. На повторном проходе русский prompt сокращается, а на финальном этапе остаётся только голосовая реплика водителя и визуальная route line.

## 9. Retrieval и transfer

Через одну-две карточки нужно вернуть ранее встреченную фразу без полного отображения транслитерации. Например, после `Сколько стоит?` пользователь видит вопрос: **«Водитель называет цену. Что ты скажешь, если хочешь ехать по счётчику?»** и выбирает/произносит `ตามมิเตอร์`.

Transfer должен менять только один параметр за раз. Сначала вместо аэропорта появляется «кондо», затем меняется направление, затем меняется способ оплаты. Нельзя одновременно менять destination, скорость речи, тип вопроса и pronunciation focus.

| Transfer level | Новая ситуация | Что сохраняется |
|---|---|---|
| A | До кондо, пожалуйста | Структура destination request |
| B | Прямо, потом направо | Navigation pattern |
| C | Ночью дороже? | Price question pattern |
| D | Вызвал Grab, жду у входа | Taxi domain, но новый service context |

## 10. Mastery gate

Урок считается освоенным не после просмотра всех карточек, а после трёх наблюдаемых действий:

| Критерий | Минимум |
|---|---|
| Recognition | Пользователь правильно выбирает смысл 5 из 6 core phrases |
| Guided production | Успешно произносит 4 из 6 фраз с подсказкой |
| Delayed retrieval | Через короткий интервал вспоминает минимум 3 фразы без транслитерации |
| Transfer | Проходит изменённый маршрут до нового destination |
| Repair | Знает хотя бы одну стратегию на случай непонимания |

Если mastery не достигнут, пользователь не видит красный «провал». Taika предлагает конкретное сокращённое повторение: **«Повторим только destination и остановку»**. На следующий день возвращаются две слабые фразы и одна уже освоенная для уверенности.

## 12. Что не нужно делать в этом уроке

Не нужно показывать крупный Thai text на каждой карточке, добавлять 15–20 фраз «на всякий случай», повторять одинаковое «спасибо» в нескольких местах без новой функции, показывать несколько score rings подряд или автоматически переводить пользователя к следующему этапу. Не нужно превращать урок в экзамен на идеальный акцент.

Эталонный урок должен ощущаться как маленькая удачная поездка: пользователь понимает задачу, говорит несколько нужных вещей, получает один понятный pronunciation cue и в конце действительно может пройти короткий taxi dialogue.

## Итоговая формула

**Один урок = один завершённый сценарий + шесть основных фраз + один pronunciation focus на попытку + одно retrieval + один transfer + понятный mastery gate.**

Если этот формат работает на «Такси», его можно перенести на «Рынок», «Еду», «Доктора», «Кондо» и «Иммиграцию», меняя сценарный outcome, а не просто заменяя набор слов.
