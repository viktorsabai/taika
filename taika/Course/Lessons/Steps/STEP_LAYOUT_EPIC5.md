# Вёрстка текста в карточках Step (EPIC 5)

## Текущее состояние после правок

### Учебные карточки (слово / фраза / сленг)
- **Иерархия:** RU (крупно) → транскрипция (акцент) → тайский (вторичный).
- **Лимиты строк:** title 4, phonetic 3, thai 4 (`Theme.StepCardText`) — длинные фразы не обрезаются в «...».
- **Масштабирование:** `minimumScaleFactor` 0.70 / 0.72 / 0.78 — текст сжимается при нехватке места, остаётся читаемым.
- **Распределение:** центральный блок с `frame(maxHeight: .infinity)` и Spacer сверху/снизу — контент визуально по центру карточки при любой длине текста.

### Лайфхаки
- Тот же ритм: Spacer → контент с `maxHeight: .infinity` → Spacer.
- До 8 строк, `minimumScaleFactor` 0.76, `lineSpacing(5)` для удобочитаемости.

---

## Плюсы текущего подхода
- Один контракт карточки (CardBase) для учебных и лайфхаков — единый стиль.
- Центрирование и чёткая иерархия (RU → phonetic → TH) соответствуют EdTech-подходу «фокус на одной фразе».
- Минимализм: без лишних блоков, только текст и CTA.
- Масштабируемость через `Theme.StepCardText` — лимиты и scale в одном месте.

## Минусы / риски
- Очень длинные фразы (4+ строки) могут занимать всю карточку; тайский блок может уезжать вниз — при необходимости можно ввести «свёртку» (показать первые N строк + «ещё»).
- На маленьких экранах при 4 строках title шрифт может сжаться до 0.7 — порог читаемости на грани; при необходимости поднять `titleScale` до 0.75.
- Лайфхаки с 8 строками на низких карточках теоретически могут обрезаться — высота лайфхак-карты уже зафиксирована под контент.

---

## Рекомендации (идеальный EdTech user flow без потери минимализма)

1. **Не резать контент** — лучше перенос и масштаб, чем «...» в середине фразы (сделано через StepCardText лимиты).
2. **Один ритм для учебных и лайфхаков** — одинаковые отступы, spacing, вертикальный баланс (Spacer + maxHeight) — уже единообразно.
3. **При росте контента** — если появятся карточки с 2–3 абзацами (например, грамматические подсказки), рассмотреть отдельный layout: заголовок + скролл/свёртка тела текста, не меняя текущие компактные карточки.
4. **Читаемость** — не опускать `minimumScaleFactor` ниже 0.70 для основного текста; для подписей (тайский, footnote) допустимо 0.75–0.78.
5. **Функциональность** — play / лайк / запомнил остаются на месте; вёрстка меняет только текстовый блок и его лимиты, не логику.
